## Known Issues & Limitations

### 1. S3 URI Support (Not Implemented)

**Status**: S3 URIs (`s3://`) are not supported and fall back to FakeLanceDataset

**Workaround**: Use OSS URIs (`oss://`) or local file URIs

**Future**: Add S3 support when lance-java SDK supports it

### 2. Registry Clear() Not Atomic

**Status**: `clear()` is not atomic with respect to concurrent `getOrLoad()` calls

**Impact**: New datasets may be loaded while clear() is in progress

**Recommendation**: Use `invalidate(uri)` for specific datasets instead

### 3. URI Intern() for Locking

**Status**: Uses `uri.intern()` for per-URI locking

**Impact**: Interned strings live in perm-gen (negligible for <100 URIs)

**Alternative**: Could use striped lock for better scalability

## Operational Procedures

### Starting ES with Lance Plugin (OSS)

```bash
# 1. Set environment variables in parent shell
export OSS_ACCESS_KEY_ID=$(grep '"access_key_id"' ~/.oss/credentials.json | cut -d'"' -f4)
export OSS_ACCESS_KEY_SECRET=$(grep '"access_key_secret"' ~/.oss/credentials.json | cut -d'"' -f4)
export OSS_ENDPOINT="oss-ap-southeast-1.aliyuncs.com"

# 2. Start ES
cd build/distribution/local/elasticsearch-9.2.4-SNAPSHOT
./bin/elasticsearch

# 3. Verify environment
ES_PID=$(cat elasticsearch.pid)
cat /proc/$ES_PID/environ | tr '\0' '\n' | grep OSS
```

## Rollback Procedures

### If Issues Detected During Soak Test

1. **Stop ES**: `./bin/elasticsearch stop -p elasticsearch.pid`
2. **Collect Diagnostics**:
   - `logs/elasticsearch.log`
   - `jmap -dump:format=b,file=heap.bin $ES_PID`
   - `jstack $ES_PID > thread_dump.txt`
3. **Analyze**: Review logs for patterns (OOM, timeout, errors)
4. **Rollback**: Revert to previous version, restart
5. **Report**: Document findings in `findings.md`
