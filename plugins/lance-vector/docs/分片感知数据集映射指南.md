# Lance Vector 插件 - 分片感知数据集映射指南

## 概述

Lance Vector 插件支持两种数据集映射模式：

### 传统模式（单一数据集）
所有分片共享同一个 Lance 数据集。适用于单分片索引或测试场景。

### 分片感知模式（每分片独立数据集）
每个分片读取自己的 Lance 数据集。多分片场景下的正确行为，支持线性扩展。

---

## 配置方式

### 传统模式配置

```json
{
  "mappings": {
    "properties": {
      "embedding": {
        "type": "lance_vector",
        "dims": 768,
        "similarity": "cosine",
        "storage": {
          "type": "external",
          "uri": "oss://bucket/dataset.lance",
          "lance_id_column": "_id",
          "lance_vector_column": "vector"
        }
      }
    }
  }
}
```

**特点**：所有分片共享 `dataset.lance`，适合小规模数据或单分片索引。

### 分片感知模式配置

```json
{
  "mappings": {
    "properties": {
      "embedding": {
        "type": "lance_vector",
        "dims": 768,
        "similarity": "cosine",
        "storage": {
          "type": "external",
          "uri_prefix": "oss://bucket/production",
          "shard_path": "{index}/shard-{shard_id}",
          "dataset_name": "vectors.lance",
          "lance_id_column": "_id",
          "lance_vector_column": "vector"
        }
      }
    }
  }
}
```

**解析后的 URI 格式**：`{uri_prefix}/{shard_path}/{dataset_name}`

**示例**：分片 0 解析为 `oss://bucket/production/我的索引/shard-0/vectors.lance`

---

## 模板变量

| 变量 | 替换为 | 示例 |
|------|--------|------|
| `{index}` | ES 索引名称 | `product-vectors` |
| `{shard_id}` | 数字分片 ID（从 0 开始） | `0`、`1`、`2` |

---

## 关键不变量

**数据管道必须使用与 Elasticsearch 相同的 `_id` 路由**：`hash(_id) % number_of_shards`

如果数据管道使用不同的路由，分片 N 的 Lance 数据集将包含不属于该分片的文档向量，导致召回率为零。

**ES 使用 Murmur3 哈希函数进行 `_id` 路由**。Python 生成器脚本中包含简化版 `es_shard_for_id()` 函数来近似此行为。

---

## 不支持的功能

| 不支持 | 原因 | 替代方案 |
|--------|------|----------|
| 动态分片分裂/合并 | Lance 数据集是外部预构建的 | 重建索引 + 重建数据集 |
| 自定义 `_routing` | 破坏 `hash(_id) % N` 不变量 | 仅使用默认路由 |
| ES → Lance 写路径 | Phase 1 仅支持只读 | 未来版本 |

## 数据管道要求

### 1. 分片分区

构建 Lance 数据集时，必须使用与 ES 相同的哈希路由按目标分区分区向量：

```python
def es_shard_for_id(doc_id: str, num_shards: int) -> int:
    """复制 ES 默认 _id 路由：Murmur3 hash mod num_shards"""
    import hashlib
    h = int(hashlib.md5(doc_id.encode()).hexdigest(), 16)
    return h % num_shards

# 示例：将文档路由到正确的分片
for doc_id, vector in documents:
    shard_id = es_shard_for_id(doc_id, num_shards=5)
    shard_data[shard_id].append((doc_id, vector))
```

### 2. 索引构建

为每个分片的数据集独立构建 IVF-PQ 或 HNSW 索引：

```python
import lance

for shard_id in range(num_shards):
    dataset_path = f"shard-{shard_id}/vectors.lance"
    ds = lance.dataset(dataset_path)
    ds.create_index("vector", index_type="IVF_PQ", num_partitions=256)
```

### 3. OSS 上传

将每个分片的数据集上传到解析后的 URI 路径：

```bash
# 示例：上传分片数据集到 OSS
ossutil cp shard-0/vectors.lance oss://bucket/production/product-vectors/shard-0/ -r
ossutil cp shard-1/vectors.lance oss://bucket/production/product-vectors/shard-1/ -r
# ...
```

### 4. 验证

验证每个分片的数据集仅包含会路由到该分片的文档：

```python
# 验证脚本示例
for shard_id in range(num_shards):
    ds = lance.dataset(f"shard-{shard_id}/vectors.lance")
    for doc_id in ds.to_arrow()['_id'].to_pylist():
        expected_shard = es_shard_for_id(doc_id, num_shards)
        assert expected_shard == shard_id, f"文档 {doc_id} 应该在分片 {expected_shard}，但发现于分片 {shard_id}"
```

## 向后兼容性

使用 `storage.uri` 的现有索引继续正常工作。分片感知字段（`uri_prefix`、`shard_path`、`dataset_name`）仅在存在 `uri_prefix` 时生效。

### 迁移路径

从传统模式迁移到分片感知模式：

1. **重建数据管道**：使用分片感知路由生成新的分片数据集
2. **更新索引映射**：添加 `uri_prefix`、`shard_path`、`dataset_name` 字段
3. **验证查询结果**：确保召回率与预期一致

---

## 查询行为

在分片感知模式下，每个分片的查询执行器独立地：

1. **解析数据集 URI**：使用 `{index}` 和 `{shard_id}` 解析
2. **打开数据集**：通过 URI 缓存加载（每 URI 缓存一次）
3. **执行 ANN 搜索**：获取 top-K 候选
4. **连接结果**：与 Lucene `_id` 索引连接以应用过滤器

这确保每个分片仅搜索自己的向量，实现随分片数线性扩展。

## 常见问题

### Q1: 分片感知模式与传统模式有什么区别？

**传统模式**：所有分片共享一个数据集，适合单分片或测试。

**分片感知模式**：每个分片有自己的数据集，多分片场景下的正确选择，支持线性扩展。

### Q2: 如何选择使用哪种模式？

- **索引分片数 = 1**：两种模式都可以，传统模式更简单
- **索引分片数 > 1**：必须使用分片感知模式，否则会出现数据不一致

### Q3: 数据管道如何确保数据路由正确？

数据管道必须使用与 ES 相同的哈希函数和路由逻辑：

```python
import hashlib
def es_shard_for_id(doc_id: str, num_shards: int) -> int:
    h = int(hashlib.md5(doc_id.encode()).hexdigest(), 16)
    return h % num_shards
```

### Q4: 如何验证数据集是否正确分区？

1. 检查每个分片数据集的文档 ID 是否都属于该分片
2. 运行查询验证召回率是否符合预期
3. 对比查询结果与原始文档分布

### Q5: 分片数可以动态调整吗？

不可以。分片数在索引创建时确定，更改分片数需要重建索引和数据集。

### Q6: OSS 访问失败如何排查？

1. 检查环境变量是否设置：
   ```bash
   export OSS_ACCESS_KEY_ID=your_key
   export OSS_ACCESS_KEY_SECRET=your_secret
   export OSS_ENDPOINT=oss-ap-southeast-1.aliyuncs.com
   ```

2. 检查 OSS 凭据文件：`~/.oss/credentials.json`

3. 验证 OSS 路径格式：`oss://bucket/path/to/dataset.lance`
